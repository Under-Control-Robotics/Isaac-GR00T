# GR00T RL Finetuning Guide

This guide explains how to use the RL finetuning feature to train a value function for your robot policy.

## Overview

The RL finetuning pipeline:
1. **Freezes** the policy (backbone + action head)
2. **Trains** only the value function head
3. Uses reward/value labels from your dataset

## Requirements

### 1. Dataset with Reward Labels

Your dataset must have a `reward_labels.json` file generated by the data processing pipeline:

```bash
# Generate reward labels for your dataset
python /data/anthony/ucr_vla/src/ucr_vla/data/generate_dataset_rl.py \
  --bags <your_bags> \
  --output <dataset_name> \
  --label-rewards \
  --cfail 10000.0
```

### 2. Pretrained Policy

You need a pretrained GR00T model (with backbone + action head):
- HuggingFace model: `nvidia/GR00T-N1.5-3B`
- Or your own finetuned checkpoint

## Usage

### Basic Command

```bash
python scripts/gr00t_rl_finetune.py \
  --dataset-path /data/anthony/ucr_vla/output/1129/sim_pick_box_1125_1 \
  --output-dir /tmp/gr00t_rl_value \
  --base-model-path nvidia/GR00T-N1.5-3B \
  --data-config fourier_gr1_arms_only \
  --batch-size 32 \
  --max-steps 10000 \
  --learning-rate 1e-4
```

### Multiple Datasets

```bash
python scripts/gr00t_rl_finetune.py \
  --dataset-path /path/to/dataset1 /path/to/dataset2 \
  --output-dir /tmp/gr00t_rl_value \
  --base-model-path nvidia/GR00T-N1.5-3B \
  --batch-size 32 \
  --max-steps 10000
```

### Advanced Options

```bash
python scripts/gr00t_rl_finetune.py \
  --dataset-path /data/anthony/ucr_vla/output/1129/sim_pick_box_1125_1 \
  --output-dir /tmp/gr00t_rl_value \
  --base-model-path nvidia/GR00T-N1.5-3B \
  --data-config fourier_gr1_arms_only \
  --batch-size 32 \
  --max-steps 10000 \
  --learning-rate 1e-4 \
  --value-hidden-dim 1024 \
  --value-dropout 0.1 \
  --num-gpus 4 \
  --save-steps 500
```

## Key Parameters

### Model Architecture
- `--value-hidden-dim`: Hidden dimension for value MLP (default: 1024)
- `--value-dropout`: Dropout rate (default: 0.1)

### Training
- `--learning-rate`: Learning rate (default: 1e-4)
- `--weight-decay`: Weight decay (default: 1e-5)
- `--max-steps`: Number of training steps (default: 10000)
- `--batch-size`: Batch size per GPU (default: 32)

### Hardware
- `--num-gpus`: Number of GPUs to use (default: 1)
- `--dataloader-num-workers`: Data loading workers (default: 12)

## What Gets Trained

**FROZEN (not trained):**
- Backbone Vision Tower
- Backbone LLM
- Action Head Projector
- Action Head DiT (flow matching)

**TRAINED:**
- Value Head MLP (2 layers)

## Model Architecture

```
Input: VLM embeddings from backbone
  ↓
Value Head:
  Linear(hidden_size=1536 → 1024)
  ReLU
  Dropout(0.1)
  Linear(1024 → 1)
  Clamp to (-1, 0]
  ↓
Output: Value prediction per timestep
```

## Value Function Details

- **Range**: Values are clipped to (-1, 0]
  - 0 = best (successful task completion)
  - -1 = worst (early failure)
- **Loss**: MSE loss between predicted and target values
- **Target values**: Loaded from `reward_labels.json`

## Output

The trained model checkpoint will include:
- Frozen policy weights (backbone + action head)
- Trained value head weights
- Config with `enable_rl=True` flag

## Loading the Trained Model

```python
from gr00t.model.gr00t_n1 import GR00T_N1_5

# Load model with trained value head
model = GR00T_N1_5.from_pretrained(
    "/tmp/gr00t_rl_value/checkpoint-10000",
    enable_rl=True
)

# Model will have:
# - model.backbone (frozen)
# - model.action_head (frozen)
# - model.value_head (trained)
```

## Notes

1. **Dataset Format**: Must have `reward_labels.json` file
2. **Model Loading**: Uses `strict=False` to handle pretrained models without value head
3. **Separate Training**: This is separate from normal policy finetuning (`gr00t_finetune.py`)
4. **Value-Only**: Only the value function is trained, policy remains frozen
